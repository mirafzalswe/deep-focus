# Обновления через GitHub Releases с заглушкой вместо источника

## Контекст

Бриф требует обновление приложения (R150), но не говорит откуда. Пользователь согласился на GitHub Releases и сам опубликует приложение; имени владельца и репозитория у нас нет.

## Решение

Приложение проверяет обновления через electron-updater с провайдером GitHub. Владелец и репозиторий — заглушка, пока она не заменена, проверка выключена и в настройках об этом написано. Обновление не скачивается само: пользователь запускает проверку, а установка выполняется при выходе. Значения в коде и в конфигурации сборки обязаны совпадать, это проверяет тест.

## Почему

- **Подставить придуманное имя репозитория** отвергнуто: приложение ходило бы по несуществующему или чужому адресу, а единственный разрешённый сетевой вызов должен идти только по адресу, который выбрал пользователь.
- **Оставить проверку включённой и молча падающей** отвергнуто: нечестный статус, пользователь не поймёт, что обновления не работают.
- **Не делать обновления вовсе** отвергнуто: это прямое требование брифа.
- Альтернативные источники (собственный сервер и т. п.) в источниках не рассматривались; пользователь выбрал GitHub.

## Последствия

- Обновления не работают, пока пользователь не заполнит владельца и репозиторий в двух местах, не опубликует релиз и не пересоберёт приложение. Это записано как открытый вопрос.
- Причина, почему автоматическая загрузка выключена, в источниках не зафиксирована: пользователю придётся запускать проверку вручную.
- Из-за отсутствия подписи (ADR 0006) новая версия может каждый раз встречать предупреждение SmartScreen.
- Проверка обновлений — единственный сетевой вызов приложения; любой новый вызов наружу нарушит обещание приватности.
