## Что должно заработать

Проект ставится с нуля в чистом клоне командами из README. После перезапуска приложения вместе с сессией возвращается её звук. Строгий режим нельзя обойти кнопкой «Стоп». Плавное затухание при остановке звука действительно плавное.

## Критерии приёмки

Находки независимой приёмки (клон с нуля, запуск):

- [ ] В чистом клоне `npm ci` и `npm install` падают: npm запускает `node-gyp rebuild` для better-sqlite3@13.0.3 («Could not find any Visual Studio installation to use»), хотя готовые prebuild есть; рабочая папка этого не показывает, т.к. `node_modules` уже стоят. Каким должно быть: в чистом клоне на машине без Visual Studio установка проходит командами из README (с `NODE_OPTIONS=--use-system-ca` в этой сети) и `npm run check`/`npm run build` зелёные; проверено реальным клоном во временную папку.
- [ ] После перезапуска (выход с «продолжить» и после аварийного завершения) сессия восстанавливается, а звук сессии (профиль с «включать при старте сессии») — нет: `audio.playing=false`. Каким должно быть: восстановленная идущая Focus-сессия возвращает звук по тем же правилам, что и старт (рабочий профиль для Focus, поведение перерыва для перерыва); тест.
- [ ] В Strict «Стоп» (и Skip Session / Reset / смена режима, которые завершают Focus) без подтверждения завершает сессию и за секунду снимает блокировку. Каким должно быть: пока `strictLocked`, такие команды требуют того же подтверждения, что и снятие блокировки (ожидание + фраза), либо недоступны до конца интервала; Пауза — по `keepBlockingOnPause`; выход из приложения через трей по-прежнему всегда доступен и снимает блокировку (R69); интерфейс объясняет это; тест.
- [ ] Плавное затухание не подтверждено: индикатор звука гаснет за ≤0,3 с при `fadeOutMs` 1,5 с. Каким должно быть: выяснить, затухает ли реальный выход (gain) за `fadeOutMs`; если нет — исправить; если да — статус «играет» держится до конца затухания либо индикатор отражает затухание; тест на значение gain во времени.
