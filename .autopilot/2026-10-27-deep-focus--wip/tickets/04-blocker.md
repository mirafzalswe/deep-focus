## Что должно заработать

Пока идёт Focus, YouTube, Instagram и другие выбранные сайты не открываются в Chrome, Edge, Firefox и других браузерах, которые следуют системному прокси. Права администратора не нужны. Правила переключаются на правила перерыва и снимаются после сессии. Расписание работает и без сессии. Strict требует ожидания и фразы. Статус блокировки честный: если механизм не сработал, приложение так и пишет. Исходные настройки прокси всегда возвращаются, в том числе после сбоя.

Механизм решён пользователем: без расширения браузера («расширения для браузера пока ненужно») и без прав администратора («должен работать без этого»). Это PAC в `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` плюс локальная заглушка на 127.0.0.1 (см. §4 и «Решения по реализации»).

## Критерии приёмки

- [ ] `normalizeDomain`: схема, путь, `www.`, порт, регистр → домен; адрес с путём → домен + предупреждение; localhost, IP и домены Microsoft/Windows Update отклоняются (тесты)
- [ ] `activeDomainsFor(rules, ctx)`: Focus/перерывы по флажкам правила, расписание (дни, интервал через полночь), `keepBlockingOnPause`, Scheduled Mode без сессии (тесты)
- [ ] `buildPac`: блокируемые домены и поддомены → заглушка, остальное → DIRECT или исходный прокси пользователя (тесты, включая проверку PAC-функции в `vm`)
- [ ] PAC-сервер на 127.0.0.1 со случайным портом: HTTP к заблокированному → страница «Заблокировано Deep Focus», CONNECT → отказ; URL не пишутся ни в лог, ни в БД
- [ ] `SystemProxy` (Windows): чтение исходных значений, запись `AutoConfigURL` только в HKCU, уведомление WinINET; исходное сохраняется в БД **до** первого изменения; `restore` возвращает ровно исходное
- [ ] Проверка после включения: системное разрешение прокси для заблокированного домена указывает на заглушку → `active`; иначе `error` с причиной и уведомлением, никогда не ложный `active` (тест на фейке + e2e на этой машине)
- [ ] Чужой `AutoConfigURL` → `unavailable` с объяснением, ничего не меняется; ручной `ProxyServer` сохраняется для прочих сайтов
- [ ] При старте приложения `restoreOnStartup` возвращает настройки, если прошлый запуск упал с включённой блокировкой; `--cleanup` (для деинсталлятора) возвращает настройки и выходит
- [ ] Связь с таймером: Focus → правила Focus, перерыв → правила перерыва, конец сессии → снять; ошибка блокировки не останавливает таймер
- [ ] Первое включение — экран согласия (что поменяется, что всё вернётся); без согласия реестр не трогается
- [ ] Strict: при включении объяснение, что останется доступным; снятие во время сессии — ожидание `strictUnlockDelaySec` + фраза; выход из приложения всегда снимает блокировку
- [ ] Раздел Blocker: правила по категориям, добавление/правка/вкл-выкл, флажки Focus/перерывы, расписание, фильтр «действуют сейчас», статус с причиной, подсказки 4.8.2, 4.8.3, 4.16; вкладка Settings → Website Blocker
